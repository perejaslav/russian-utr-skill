# Правила УТР — справочник

УТР — это `упрощённый технический русский язык`. Правила опираются на принципы
ГОСТ Р 58049-2017. Этот справочник излагает принципы своими словами. Он не
воспроизводит текст стандарта. Скилл не выдаёт сертификат соответствия ГОСТ.

Каждое правило описано одинаково: название, объяснение, неправильный пример,
правильный пример, признак автоматической проверки.

работает вместе с `verb-object-noun`.

## Форма предложения

### 1. Короткие предложения

**Правило.** Ориентир для инструкции — до 20 слов в предложении. Предложение
длиннее 25 слов нужно разделить. Каждое предложение несёт одну мысль.

**Почему.** Читатель без автора держит одну мысль в голове. Две мысли в одном
предложении теряются.

✗

```text
Оператор должен проверить состояние узла перед началом работы, убедиться в
готовности журнала и сообщить результат старшему инженеру до конца смены.
```

✓

```text
Перед началом работы оператор должен проверить состояние узла и готовность
журнала. До конца смены оператор должен сообщить результат старшему инженеру.
```

**Автопроверка:** да, `long-sentence`.

### 2. Жёсткий предел длины

**Правило.** Предложение длиннее 25 слов раздели в любом режиме. При делении
сохрани весь смысл.

**Почему.** Предел 25 слов одинаков для обоих режимов. Длиннее читатель не
удерживает фразу целиком.

✗

```text
Механизм повторного подключения к серверу базы данных автоматически выполняет
несколько попыток с увеличивающимися интервалами ожидания перед тем, как
вернуть клиенту последнюю ошибку соединения.
```

✓

```text
Механизм повторного подключения к серверу базы данных делает несколько попыток
автоматически. Интервал ожидания между попытками растёт. После последней попытки
механизм возвращает клиенту последнюю ошибку соединения.
```

**Автопроверка:** да, `long-sentence`.

### 3. Одна мысль — одно предложение

**Правило.** Один факт — одно утверждение. Соседние факты разделяй точкой.

**Почему.** Утверждение с двумя фактами нельзя проверить по частям.

✗

```text
Сервер вернул ошибку 503, и клиент повторил запрос.
```

✓

```text
Сервер вернул ошибку 503. Клиент повторил запрос.
```

**Автопроверка:** частично, `long-sentence` находит длину. Правило
`complex-sentence` находит число союзов.

### 4. Одна команда — одно предложение

**Правило.** Инструкция выполняет одно действие в одном предложении. Действие
и его результат стоят в разных предложениях.

**Почему.** Инструкцию выполняют по шагам. Шаг должен быть один.

✗

```text
Откройте файл `config.yaml`, измените таймаут и сохраните результат.
```

✓

```text
Откройте файл `config.yaml`. Измените таймаут. Сохраните файл.
```

**Автопроверка:** нет. Проверяет модель.

### 5. Прямой порядок слов

**Правило.** Сначала исполнитель, потом действие, потом объект. Условие стоит
перед действием, которого оно касается.

**Почему.** Обратный порядок прячет исполнителя действия. Условие после
команды читатель видит, когда команда уже выполнена.

✗

```text
После перезапуска сервера оператором сбросьте счётчик.
```

✓

```text
Когда оператор перезапустит сервер, сбросьте счётчик.
```

**Автопроверка:** нет. Проверяет модель.

### 6. Нет точки с запятой

**Правило.** Точка с запятой в техническом тексте не используется. Напиши два
предложения.

**Почему.** Знак связывает части, которые читатель держит в голове по очереди.

✗

```text
Проверьте систему; потом запустите тесты.
```

✓

```text
Проверьте систему. Потом запустите тесты.
```

**Автопроверка:** да, `semicolon`.

### 7. Одна тема в абзаце

**Правило.** Абзац раскрывает одну тему. Новая тема начинается с абзаца.

**Почему.** Абзац о двух темах прячет вторую тему.

✗

```text
Сервер принимает запрос за 40 мс. Кроме того, перед обновлением нужно сделать
копию базы данных командой pg_dump.
```

✓

```text
Сервер принимает запрос за 40 мс.

Перед обновлением сделайте копию базы данных командой `pg_dump`.
```

**Автопроверка:** нет. Проверяет модель.

## Глагол

### 8. Действительный залог

**Правило.** Назови того, кто выполняет действие. Если исполнитель неизвестен,
скажи это прямо.

**Почему.** Пассивный залог прячет исполнителя. Читатель ищет его заново.

✗

```text
Файл был сохранён сервером.
```

✓

```text
Сервер сохранил файл.
```

✗

```text
Конфигурация была изменена администратором в 14:30.
```

✓

```text
Администратор изменил конфигурацию в 14:30.
```

**Автопроверка:** да, `passive-voice`. Уровень advisory.

### 9. Повелительное наклонение

**Правило.** Инструкция начинается с глагола во втором лице. Описание
использует форму инфинитива или третьего лица.

**Почему.** Читатель выполняет шаг. Ему не нужен рассказ о чём-либо.

✗

```text
Необходимо открыть файл `config.yaml` перед запуском.
```

✓

```text
Откройте файл `config.yaml` перед запуском.
```

**Автопроверка:** нет. Проверяет модель.

### 10. Глагол вместо отглагольного существительного

**Правило.** Действие называй глаголом. Отглагольное существительное прячет
исполнителя.

**Почему.** Пара `выполнить проверку` читается дольше и ничего не добавляет.

✗

```text
Произвести установку пакета.
Выполнить проверку журнала.
Осуществить проверку состояния.
Произвести изменение настроек.
```

✓

```text
Установите пакет.
Проверьте журнал.
Проверьте состояние.
Измените настройки.
```

✗

```text
Обработка запросов, проверка ответов и сохранение результатов выполняются
сервером в фоне.
```

✓

```text
Сервер в фоне обрабатывает запросы, проверяет ответы и сохраняет результаты.
```

**Автопроверка:** да, `verb-object-noun` и `nominalization`.

### 11. Нет канцеляризмов

**Правило.** Убери служебный оборот. Назови действие прямо.

**Почему.** Канцелярит прячет действие за общим словом.

✗

```text
В настоящее время сервис недоступен.
В рамках программы обновляется сервер.
Представляется необходимым проверить состояние.
Проверьте данный модуль.
```

✓

```text
Сейчас сервис недоступен.
Сервер обновляют по программе.
Нужно проверить состояние.
Проверьте модуль.
```

**Автопроверка:** да, `bureaucratism`. Полная таблица замен — в
`references/glossary.md`.

### 12. Нет длинных причастных оборотов

**Правило.** Причастный оборот разверни в глагольное предложение. То же самое
с деепричастным оборотом.

**Почему.** Оборот отрывает действие от исполнителя.

✗

```text
Файл, сохранённый сервером, удалён после проверки журнала.
```

✓

```text
Сервер сохранил файл. После проверки журнала файл удалён.
```

✗

```text
Закрыв соединение с клиентом, сервер перезапускается.
```

✓

```text
Сервер закрывает соединение с клиентом. Потом сервер перезапускается.
```

**Автопроверка:** да, `participle-clause`. Нужна библиотека `pymorphy3`.

### 13. Фактический порядок действий

**Правило.** Шаги идут в том порядке, в котором их выполняют. Не меняй
порядок ради красоты.

**Почему.** Инструкция с неверным порядком шагов невыполнима.

✗

```text
1. Запустите сервер.
2. Установите пакет.
```

✓

```text
1. Установите пакет.
2. Запустите сервер.
```

**Автопроверка:** нет. Проверяет модель.

## Слова

### 14. Один термин — одно понятие

**Правило.** Одно понятие называй одним словом во всём тексте. Разные слова
для одного действия запрещены.

**Почему.** Читатель не знает, два это предмета или один.

✗

```text
Проверьте конфигурацию. Затем валидируйте ответ сервера.
```

✓

```text
Проверьте конфигурацию. Потом проверьте ответ сервера.
```

**Автопроверка:** да, `synonym-rotation`. Проверка идёт по всему файлу.

### 15. Нет синонимов ради разнообразия

**Правило.** Не меняй глагол без нужды. Красота текста — не причина.

**Почему.** Смена слова читается как смена действия.

✗

```text
Удалите файл. Затем стирайте кэш. Потом снесите образ.
```

✓

```text
Удалите файл. Потом удалите кэш. Потом удалите образ.
```

**Автопроверка:** да, `synonym-rotation`.

### 16. Короткие цепочки существительных

**Правило.** Не ставь подряд больше трёх существительных. Добавь глагол или
предлог.

**Почему.** Читатель теряет, где кончается определение и начинается имя.

✗

```text
Настройка серверного модуля распределения нагрузки выполнена.
```

✓

```text
Модуль распределения нагрузки на сервере настроен.
```

**Автопроверка:** да, `noun-chain`. Нужна библиотека `pymorphy3`.

### 17. Понятные местоимения

**Правило.** Укажи предмет. Не пиши `он`, `это`, `данный` вместо имени.

**Почему.** У местоимения несколько возможных целей.

✗

```text
Откройте файл `config.yaml`. Измените в нём значение `timeout`. Сохраните его.
```

✓

```text
Откройте файл `config.yaml`. Измените в файле значение `timeout`. Сохраните
файл.
```

**Автопроверка:** нет. Проверяет модель.

### 18. Нет метафор

**Правило.** Технический текст пиши буквально. Образ не помогает выполнить
действие.

**Почему.** Метафора переносит смысл на другой предмет.

✗

```text
Сервер поперхнулся и не смог обработать запрос.
```

✓

```text
Сервер не смог обработать запрос.
```

**Автопроверка:** нет. Проверяет модель.

### 19. Термин объяснён при первом употреблении

**Правило.** Новый термин объясни при первом употреблении. Дальше используй
термин без пояснений.

**Почему.** Термин без пояснения останавливает читателя.

✗

```text
Запустите идемпотентный планировщик задач.
```

✓

```text
Запустите идемпотентный планировщик задач. Идемпотентный — значит повторный
запрос не создаёт вторую задачу.
```

**Автопроверка:** нет. Проверяет модель.

## Точность

### 20. Конкретные значения

**Правило.** Вместо оценочного признака укажи число, срок или имя. Проверяемость
важнее мягкости. Значение бери из исходного текста или спроси у автора. Не
придумывай его.

**Почему.** Оценочный признак невозможно проверить.

✗

```text
Установите достаточно большой таймаут — 5 секунд.
Сделайте это как можно скорее, до 14:00.
Ответ приходит в ряде случаев: при статусе 429.
```

✓

```text
Установите таймаут 5 секунд.
Сделайте это до 14:00.
Ответ приходит при статусе 429.
```

**Автопроверка:** да, `vague-formulation`.

### 21. Нет маркетинговых обещаний

**Правило.** Убери похвалу, которую нельзя измерить. Если в тексте есть
измерение, оставь его.

**Почему.** Обещание без измерения нельзя проверить.

✗

```text
Уникальный инновационный модуль обрабатывает 1000 запросов в секунду.
```

✓

```text
Модуль обрабатывает 1000 запросов в секунду.
```

**Автопроверка:** да, `marketing-word`.

### 22. Точность важнее краткости

**Правило.** Если упрощение ухудшает точность, оставь сложную формулировку.
Сообщи об этом строкой `Оставлено как есть:`.

**Почему.** Короткая неверная фраза опаснее длинной верной.

✗

```text
Ответ придёт за пять дней.
```

✓

```text
Ответ придёт в течение пяти рабочих дней.

Оставлено как есть: «в течение пяти рабочих дней» — точность срока важнее
краткости.
```

**Автопроверка:** нет. Проверяет модель.

## Структура

### 23. Списки для последовательностей

**Правило.** Три и более шагов оформи списком. Элемент списка не заканчивай
союзом.

**Почему.** Последовательность в одном предложении теряет порядок.

✗

```text
Откройте панель, найдите нужный раздел и
нажмите кнопку.
```

✓

```text
1. Откройте панель.
2. Найдите нужный раздел.
3. Нажмите кнопку.
```

**Автопроверка:** частично, `dangling-conjunction` находит незаконченный союз.

### 24. Предупреждение перед действием

**Правило.** Назови опасность до начала работы. Не прячь предупреждение в
конец абзаца.

**Почему.** Читатель выполняет шаг до конца абзаца.

✗

```text
Очистите каталог `C:\data`. Внимание: команда удаляет все данные без
возможности восстановления.
```

✓

```text
Осторожно: команда удаляет все данные без возможности восстановления.
Очистите каталог `C:\data`.
```

**Автопроверка:** нет. Проверяет модель.

## Смысл

### 25. Предположение остаётся предположением

**Правило.** Не превращай «может», «вероятно», «возможно» в утверждение.
Уверенность автора — это содержание.

**Почему.** Утверждение вместо предположения меняет смысл текста.

Исходный текст: `Ваш запрос не обработан, возможно, из-за перегрузки сервера`.

✗

```text
Ваш запрос не обработан, потому что сервер перегружен.
```

✓

```text
Ваш запрос не обработан. Возможно, причина в перегрузке сервера.
```

Исходный текст: `Ошибку может вызывать устаревшая версия клиента`.

✗

```text
Ошибка вызвана устаревшей версией клиента.
```

✓

```text
Причиной ошибки может быть устаревшая версия клиента.
```

**Автопроверка:** нет. Линтер не проверяет модальность намеренно.

### 26. Ничего не теряй

**Правило.** Сохрани условия, ограничения, числа, даты, единицы измерения,
версии, пути, команды и имена параметров.

**Почему.** Любая потеря меняет действие читателя.

Исходный текст: `Установите таймаут 5 секунд вместо 30 секунд`.

✗

```text
Установите таймаут покороче.
```

✓

```text
Установите таймаут 5 секунд вместо 30 секунд.
```

✗

Исходный текст: `Запустите make build OPT=1`.

```text
Запустите команду сборки с флагом оптимизации.
```

✓

```text
Запустите `make build OPT=1`.
```

**Автопроверка:** нет. Проверяет модель.

### 27. Ничего не добавляй

**Правило.** Не придумывай причину, рекомендацию, срок или механизм. Если
информации нет в исходном тексте, её не должно быть в ответе.

**Почему.** Лишняя деталь выглядит как правдивый факт.

Исходный текст: `Проверьте журнал`.

✗


## Что линтер не проверяет

Линтер проверяет форму текста. Он не понимает смысл. Эти проверки
делает модель:

1. Двусмысленность фразы.
2. Логическая связь предложений.
3. Понятность местоимения.
4. Порядок информации в инструкции.
5. Потеря смысла при переписывании.
6. Необходимость структуры.
7. Один термин на одно понятие во всём тексте.
8. Степень уверенности автора не должна меняться.

## Что линтер не делает

Линтер не меняет текст. Он только показывает нарушения. Линтер не выдаёт
оценку соответствия ГОСТ Р 58049-2017. Линтер не знает отраслевого
словаря.
