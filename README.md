# russian-utr-skill

Скилл для LLM-агента. Он упрощает русские технические тексты по правилам УТР и
не меняет их смысл.

Принципы УТР опираются на положения ГОСТ Р 58049-2017. Скилл излагает принципы
своими словами. Он не воспроизводит текст стандарта. Он не выдаёт сертификат
соответствия ГОСТ.

## Что такое УТР

УТР — это `упрощённый технический русский язык`. Его задача одна: текст читают
одинаково. Автора нет рядом с читателем. Уточнить нельзя.

Русский технический текст страдает от трёх болезней:

- канцелярит прячет действие за служебным оборотом
- отглагольные существительные прячут исполнителя действия
- расплывчатые формулировки нельзя проверить.

УТР лечит именно их. Правила простые: короткие предложения, действительный
залог, глагол вместо существительного, одно обозначение для одного действия.

## Для чего нужен скилл

Скилл нужен там, где ошибка понимания стоит дорого:

- инструкции и регламенты
- эксплуатационная документация
- технические задания
- описания API, форматов и параметров
- системные промпты
- сообщения об ошибках программы
- диагностика и устранение неполадок
- предупреждения о безопасности
- сообщения между агентами
- README и тексты с объяснениями.

## Два режима

| Режим | Когда использовать | Строгость |
| --- | --- | --- |
| `STRICT` | инструкции, ошибки, промпты, ТЗ, API, диагностика | максимальная |
| `NORMAL` | README, обзоры, обучение, ответы пользователю | базовая |

Разница только в строгости. Смысл сохраняется в обоих режимах.

В режиме `NORMAL` предел 20 слов становится рекомендацией. Предел 25 слов
действует в обоих режимах. Остальные правила ясности и однозначности тоже
действуют всегда.

Если режим не указан, агент определяет его по типу текста. Инструкция и ошибка
дают `STRICT`. Обзор и README дают `NORMAL`.

## Пример

**Было**

```text
Возникла ошибка при обработке запроса, которая, вероятно, связана с тем, что
формат переданных данных не соответствует ожидаемому, и в случае если данные
были переданы в устаревшем формате, сервер возвращает код 400.
```

**Стало**

```text
При обработке запроса возникла ошибка.

Вероятная причина: формат переданных данных не соответствует ожидаемому.

Если данные переданы в устаревшем формате, сервер возвращает код 400.
```

Слово «вероятно» осталось в форме «вероятная причина». Автор не уверен в
причине, и скилл не имеет права сделать её фактом. Скилл не добавил советов,
которых нет в исходном тексте.

Другие примеры: `examples/before-after.md`. Там 18 случаев по десяти типам
текста.

## Что скилл не делает

- Не выдаёт сертификат соответствия ГОСТ Р 58049-2017.
- Не проверяет смысл и логику текста.
- Не заменяет рецензию специалиста.
- Не превращает пустой текст в содержательный.
- Не улучшает текст, в котором нет фактуры.
- Не меняет смысл ради краткости.

## Установка

Формат скилла — свободный стандарт Agent Skills
([agentskills.io](https://agentskills.io/specification)). Формат понимают
Claude Code, OpenCode, Codex, Gemini CLI, Cursor, Pi, Oh My Pi и Goose. Скилл не
зависит от инструментов конкретного агента. Меняется только каталог установки.

Каталог скилла должен называться `russian-utr`. Это имя совпадает с полем
`name` в `SKILL.md`. Стандарт требует такого совпадения. Поэтому указывайте имя
каталога явно при клонировании.

### Быстрая установка

Скрипт `scripts/install.py` копирует нужные файлы скилла. Тесты и служебные
файлы Git он не копирует.

```bash
git clone https://github.com/perejaslav/russian-utr-skill
cd russian-utr-skill
python scripts/install.py
```

Без параметров скрипт ставит скилл в два каталога:

- `~/.agents/skills/russian-utr` для OpenCode, Codex, Gemini CLI, Cursor, Pi,
  Oh My Pi и Goose
- `~/.claude/skills/russian-utr` для Claude Code.

Параметры скрипта:

```bash
python scripts/install.py --list
python scripts/install.py --harness codex
python scripts/install.py --harness opencode,pi
python scripts/install.py --harness all
python scripts/install.py --project путь/к/проекту
python scripts/install.py --link
python scripts/install.py --force
python scripts/install.py --dry-run
```

Параметр `--link` создаёт символическую ссылку на клон. Тогда `git pull`
сразу обновляет скилл. В Windows символическую ссылку может создать
администратор. Обычный пользователь может её создать, если включён режим
разработчика.

### Ручная установка

Клонируйте репозиторий в каталог из таблицы. Каталог для всех проектов
указан в колонке «Пользователь». Каталог для одного проекта указан в колонке
«Проект».

| Агент | Пользователь | Проект |
| --- | --- | --- |
| Claude Code | `~/.claude/skills/` | `.claude/skills/` |
| OpenCode | `~/.agents/skills/` или `~/.config/opencode/skills/` | `.agents/skills/` или `.opencode/skills/` |
| Codex | `~/.agents/skills/` | `.agents/skills/` |
| Gemini CLI | `~/.agents/skills/` или `~/.gemini/skills/` | `.agents/skills/` или `.gemini/skills/` |
| Cursor | `~/.agents/skills/` или `~/.cursor/skills/` | `.agents/skills/` или `.cursor/skills/` |
| Pi | `~/.agents/skills/` или `~/.pi/agent/skills/` | `.agents/skills/` или `.pi/skills/` |
| Oh My Pi | `~/.agents/skills/` или `~/.omp/agent/skills/` | `.agents/skills/` или `.omp/skills/` |
| Goose | `~/.agents/skills/` | `.agents/skills/` |

Пример для общего каталога:

```bash
git clone https://github.com/perejaslav/russian-utr-skill ~/.agents/skills/russian-utr
```

Пример для Claude Code:

```bash
git clone https://github.com/perejaslav/russian-utr-skill ~/.claude/skills/russian-utr
```

OpenCode и Cursor читают также каталог `~/.claude/skills/`. Goose читает его
для совместимости. Если скилл уже стоит там, второй экземпляр не нужен.

После установки начните новую сессию агента. Агенты читают список скиллов
при запуске.

### Агенты без поддержки скиллов

Некоторые агенты не читают `SKILL.md`. Они читают файл правил проекта:
`AGENTS.md`, `CONVENTIONS.md` или похожий файл. Для такого агента скопируйте
скилл в проект и добавьте в файл правил строку:

```text
Для русского технического текста применяй правила из .agents/skills/russian-utr/SKILL.md.
```

Тогда агент прочитает `SKILL.md`, когда получит такую задачу.

### Проверка

Проверьте установку из каталога скилла:

```bash
python scripts/utr-lint.py --selftest
```

Нужен Python 3.10 или новее. Если команда `python` не найдена, используйте
`python3`.

### Необязательная зависимость

Линтер работает без зависимостей. Библиотека `pymorphy3` включает два
дополнительных правила и убирает часть ложных срабатываний.

```bash
python -m pip install -r requirements-optional.txt
```

Без неё работают 11 правил из 13. С ней работают все 13.

## Использование

Попросите агента упростить текст:

```text
Упрости этот текст по УТР
Сделай инструкцию однозначной
Убери канцеляризмы из этого описания
Проверь технический текст на правила УТР
```

По умолчанию агент возвращает только готовый текст. Ничего больше.

Если нужны объяснения, добавьте к запросу: `покажи таблицу нарушений`.
Тогда агент покажет таблицу с колонками `Нарушение`, `Было`, `Стало`,
`Причина`.

Если точность мешает сокращению, агент допишет строку
`Оставлено как есть:` и объяснит, что сохранилось.

## Линтер

Линтер проверяет форму текста. Он только анализирует и никогда не меняет
текст.

```bash
python scripts/utr-lint.py README.md
python scripts/utr-lint.py docs/ tests/
python scripts/utr-lint.py --json отчёт.md
python scripts/utr-lint.py --baseline 5 docs/
python scripts/utr-lint.py --mode normal README.md
python scripts/utr-lint.py --disable marketing-word docs/
python scripts/utr-lint.py --list-rules
python scripts/utr-lint.py --selftest
```

Читает текст из файлов или из стандартного ввода. Код завершения равен `1`,
если жёстких нарушений больше, чем указано в `--baseline`.

### Правила

| Правило | Что ищет |
| --- | --- |
| `long-sentence` | предложение длиннее предела |
| `semicolon` | точка с запятой |
| `bureaucratism` | служебный оборот |
| `verb-object-noun` | служебный глагол перед существительным |
| `nominalization` | избыток отглагольных существительных |
| `passive-voice` | вероятный пассивный залог |
| `synonym-rotation` | одно действие под разными именами |
| `complex-sentence` | много союзов в одном предложении |
| `dangling-conjunction` | незаконченный союз в элементе списка |
| `vague-formulation` | оценочный срок вместо числа |
| `marketing-word` | похвала без измерения |
| `participle-clause` | причастный или деепричастный оборот |
| `noun-chain` | четыре существительных подряд |

Правила `participle-clause` и `noun-chain` работают только с `pymorphy3`.

### Что линтер не проверяет

Модальность. Слова «может», «вероятно», «возможно» никогда не считаются
ошибкой. Уверенность автора — это содержание текста.

Двусмысленность, логику, потерю смысла и понятность местоимений проверяет
модель. Такие проверки нельзя надёжно описать регулярным выражением.

### Что не разбирается как проза

- fenced code на тройных обратных кавычках и тильдах
- YAML-фронтматтер
- inline code в кавычках
- адреса, почта, пути Windows и POSIX, флаги CLI, JSON
- текст в прямых кавычках без кириллицы.

Содержимое таблиц проверяется по ячейкам. Одна длинная ячейка даёт одну
находку, а не одну находку на всю таблицу.

## Тесты

Тесты покрывают линтер и чистоту документации.

```bash
python -m pytest tests -q
```

С морфологией запускаются дополнительные тесты:

```bash
python -m pip install pymorphy3
python -m pytest tests -q
```

Тесты проверяют: чистый русский текст, длинные предложения, канцеляризмы,
пассивный залог, списки, Markdown, inline code, fenced code, команды, адреса,
пути Windows, параметры CLI, JSON и таблицы Markdown.

## Ограничения

1. Линтер не выдаёт оценку соответствия ГОСТ Р 58049-2017.
2. Два правила требуют `pymorphy3`.
3. Словарь терминов отрасли не входит в проект. Скилл предлагает глоссарий,
   но не проверяет вашу терминологию.
4. Число слов считается по пробелам. Единицы измерения и числа в счёт не
   входят как слова.
5. Разбор таблиц поддерживает обычную форму Markdown. Другие формы
   не разбираются.
6. Проверка незаконченного союза не понимает списки внутри блоков кода.
7. Морфология `pymorphy3` выбирает самый вероятный разбор слова. Редкие слова
   и омонимы иногда разбираются неверно.
8. Правило `noun-chain` считает прилагательные частью цепочки. Короткие
   цепочки из трёх слов допустимы.
9. Скилл не проверяет смысл. Потеря смысла при переписывании остаётся на
   модели.
10. Файл `examples/linter-edge-cases.md` содержит ошибки специально.
11. Правило `marketing-word` не понимает контекст. Оно считает ошибкой
    превосходные степени вроде `лучший` и `оптимальный` даже в техническом
    смысле. Отключите правило, если такое сравнение нужно.

## Источник принципов

Принципы УТР опираются на ГОСТ Р 58049-2017 «Перевод эксплуатационной
документации на изделия авиационной техники с/на иностранные языки. Общие
положения». Раздел 8.2 стандарта задаёт общие требования к УТР. Стандарт написан для авиационной документации.
Скилл переносит его идеи на любой технический текст: однозначность, короткие
предложения, единые термины.

Репозиторий `danyuchn/asd-ste100-skill` послужил образцом архитектуры: два
режима, приоритет смысла, линтер с жёсткой логикой и фикстура краевых случаев.
Английские правила ASD-STE100 в этом проекте не используются.
